Elastic: yes, it fits

Per-second billing suits the bursts

An always-on L40S costs $577–796 a month. It only beats Modal past about 300–400 L40S-hours a month: our busiest four days, every day. It would also run sweeps one at a time, where we ran up to four GPUs at once.

Speed: probably CPU-bound

A faster GPU likely buys nothing yet

Training containers averaged one CPU core, and two changes that only added CPU work slowed a pass 41–96%. Building batches with several CPU workers is the cheapest speed-up: eight cores cost $0.38 an hour against the L40S's $1.95.

Cost: one test away

The L4 might do at 41% of the price

If the GPU is waiting on the CPU, an L4 ($0.80 an hour) may run nearly as fast as the L40S ($1.95). It hasn't been timed on the same recipe. 96 px strips already made passes 11–45% faster.

Not measured: peak GPU memory and GPU utilization were never logged. Memory is estimated at 4–15 GB, well inside the L4's 24 GB. Three timing runs, under $1 in all, would settle speed and cost (below).

What to measure next

Two one-line logging changes

  • In proto.py, print torch.cuda.max_memory_allocated() each pass: peak memory.
  • In modal_app.train, run nvidia-smi --query-gpu=utilization.gpu,memory.used -l 30 beside training: utilization every 30 s.

Three timing runs, under $1

  • D4's Boccherini stage on an L4, against its L40S time.
  • The same on an L40S with 8 CPU cores and batches built by worker processes.
  • A larger batch, if memory allows. It changes training, so it needs its own clean-test check.

Incidents and caveats
  • A spend limit at about $50 metered disabled the workspace mid-run on 18 October; two runs were lost and rerun ($0.59).
  • Modal preempted one pointer run after 24 minutes. Training can't resume, so a preempted run starts over.
  • The CPU-bound reading is inferred from billing's CPU use and from slow-downs, not measured on the GPU.
